The mapping, feature flag and proposed interest tables were absent in that metadata snapshot; migration history differs from local files. Schema and access can change and must be rechecked under approved read-only scope before any migration.
- A previously authorized aggregate check returned zero posts linked to nonpublic or missing brains at that instant. No records were modified. This does not prove future safety or test direct database access, embedded content, caches, identity, other writers or RLS.

The connected query tool does not specify these semantics. Its `create_migration` tool describes rollback on failure but also creates a migration and is **not** the approved rehearsal. Neither has been run. Do not rewrite a security-blocked query to bypass a provider filter.
- Local tests cover synthetic data only; the existing review-only proposals are not verified compatible production migrations. The server-issued 30-day retry experiment requires issuing a permit before offline use; it has no live client, complete post schema, auth bridge, limits or recovery UI.

A production-project synthetic test is not equivalent to isolated staging and carries residual risk.
3. **Visibility protection:** Independently review trigger dependencies, privilege/ownership, race conditions, direct reads/writes, lock order, hidden content/embeds and caches. Default off, monitor privacy-safe aggregates, test degradation and performance, and only then propose an owner-approved controlled rollout followed by expansion. Do not enable point losses or invent stake prices.

## Production risks, stop conditions and recovery

Risks include data loss, privacy leaks, account mislinking, disruption to existing experimental accounts, expired offline work, increased costs, deadlocks, stale caches and incorrect ranking. Current API service-role access can bypass RLS. Stop on unexpected data, unreviewed side effects, missing permissions, unexpected migration history, errors, unsafe link behavior, ownership ambiguity, or unconfirmed backup/recovery. Do not print post content, account IDs, tokens or key values. Disable experimental serving/ingestion and preserve evidence on incident; restoration or data deletion needs its own approved, visibility-aware plan. A previous backup can restore stale private links or overwrite new work, so never blindly restore it.

No delivery date or production readiness is guaranteed by this plan. A green local test or synthetic live rehearsal alone does not establish security, real scale, fairness or factual accuracy.
