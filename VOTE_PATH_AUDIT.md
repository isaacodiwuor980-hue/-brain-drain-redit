## Evidence needed before activation

Reviewed complete database and application writer/reader inventory; approved isolated verification of actual role grants, RLS, function bodies/triggers, service-role and direct-client behavior; trusted account provisioning and mapped-identity lifecycle; server-authorized visibility and five-minute session checks; atomic per-user revisions and remove-then-choose enforced across **all** writers; idempotent retry receipts, concurrency, cross-device/account-switch and uncertain-result handling; privacy and deletion across analytics/cache/backups; safe recovery/restore; real web/Android/iOS end-to-end tests. An approved, verified recovery plan and explicit owner approval are required before any live mutation. No synthetic test substitutes for these requirements.

### Direct hive helper containment (2026-11-25)
Superseding the earlier note: local `runPruning`, `runFossilization`, `runForkCheck`, and `runReactivation` now each fail closed before reading or writing storage, independently of the disabled aggregate runner. Their historical bodies remain for review; no feature flag enables them. Focused mock tests cover direct invocation only. Old builds, direct IndexedDB modifications, server/DB workers and other reputation writers are unaffected. Non-vote XP awards and streak changes still run.
- The local mounted post-create response no longer includes placeholder up/down fields; mocked HTTP regression confirms only repost is returned there. This does not remediate the unmounted legacy reaction fixture or direct DB paths.
- `enqueueAction` now preserves each newly queued held reaction rather than overwriting earlier ambiguous toggles; held post/brain actions are likewise preserved. It does not restore already-overwritten entries, provide review UI, or make queue/quarantine transfers atomic or cross-tab safe. The replay gates remain in place.
- Unknown persisted queue action types now fail closed for manual review instead of being treated as a successful skip; `add_comment` and `save_profile` retain existing local-only skip behavior and require separate review. No cross-tab or storage durability guarantee follows.
- Auth-token helper now rejects a token obtained across a user-object switch (mock test), matching existing session helper containment. It cannot prove that work was created for the current user, prevent switches after return or stop already-sent requests; old clients and other auth paths remain unverified.
- Post creation is distinct from the disabled vote writer: its client now checks local `userId` against the session before sending and rechecks after asynchronous work, but the server still needs trusted mapped ownership, audience authorization and idempotency. Local author equality is not ownership proof; in-flight and old-client paths remain unverified.
- Immediate post creation now checks offline state before a send and holds matching-account drafts for review. This does not change the disabled reaction replay, fix other network paths, or make browser connectivity a trustworthy server outcome.
- `lib/error-monitor.ts` previously sent arbitrary error messages/stacks via beacon to mounted `api-server/src/routes/client-errors.ts`, which logged the entire client object: a potential indirect vote/content leak. Outbound beacon and route-level logging are now locally paused (synthetic tests); upstream request logs, memory listeners, dev/browser consoles, historical sinks, other telemetry and old clients remain unverified. Monitoring is degraded until a privacy-reviewed alternative exists.
- Shared IndexedDB feed cache remains a risk: `reconcileCachedCloudPost` deliberately copies legacy `userReactions` into refreshed rows, and local export includes whole posts/comments/analytics. Display redaction does not restrict storage/export or other clients; no cached records were deleted. Account-scoped access, provenance and safe retention/erasure need review before launch.
- New `useSocial` query results and optimistic inserts now redact known vote fields before entering that React Query cache, including mocked fallback. This does not remove IndexedDB legacy fields or invalidate all previously loaded/other caches; export and direct database access remain blockers.
- Queue write containment now refuses malformed or unreadable pending storage and warns on failure, rather than replacing a partial view; this protects newly attempted reaction/post/brain queue writes only. Non-atomic cross-tab access, existing malformed data, unowned entries, old clients and manual recovery remain unresolved. No queue content was inspected or deleted.
- Superseding the earlier local-only skip note: all pending action types, including comments and profiles, now require review and are preserved individually on enqueue. Quarantine remains non-atomic, bounded and not a recovery interface; unowned records and older clients remain unresolved.
