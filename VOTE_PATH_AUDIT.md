# Vote path audit — local code, not live security proof

Scope: repository source review on the current branch. This is an inventory of located paths, not a guarantee that unknown clients, jobs, database triggers, functions or live grants are absent. No personal data was inspected and no live changes or tests were made.

| Surface | Local behavior / limitation |
| --- | --- |
| `api-server/src/routes/posts.ts` | Mounted `/posts/:id/react` authenticates then unconditionally returns 503; reposts are also paused. Legacy direct reaction writer is exported as an **unmounted test fixture** and cannot enforce two-step, recent auth or confidentiality. Direct DB/service clients bypass this route. |
| `api-server/src/routes/vote-state-v2.ts` | Mounted own-state read is flag-gated, checks authentication, five-minute `auth_time` and mapped identity, then unconditionally returns 503. Separately exported fixture calls an unimplemented RPC and is not authorized for use. Real visibility, atomic revision, grants and RLS remain unverified. |
| `api-server/src/routes/feed.ts` | Ordinary/following-v2 responses do not emit up/down counts or individual reactions. Query requests only repost rows and target/type columns; process cache stores counts, not voter identities. Live DB, other HTTP routes, old processes and clients remain unverified. Repost counts may be incorrect. |
| `hooks/use-social.ts`, `lib/post-votes.ts`, `lib/api/feed.ts` | Optimistic legacy reaction mutation and API client exist, but exported social-hook action hard-gates before invoking it. `PostCard` and topic-page vote controls are disabled; UI is not security enforcement. Old clients or direct calls can bypass client gate, but mounted API currently returns 503. |
| `hooks/use-comments.ts`, `feed/CommentThread.tsx` | Local IndexedDB comment up/down and House/Mouth mutation implementations remain, but public hook actions reject before mutation/analytics and controls are disabled. Vote-based sort is disabled while paused. Existing local vote fields remain stored. |
| `pages/CommunityPage.tsx` | Previously separate check-in local vote update removed; check-in selection data no longer passed to card. Existing check-in storage is untouched. |
| `lib/offline-sync.ts`, `hooks/use-offline-sync.ts` | Queued `post_reaction` requires review and replay also throws. Cross-tab, account-switch, in-flight and uncertain outcomes are not comprehensively solved. Historical queues are retained, no complete review UI exists. |
| `lib/analytics.ts`, `api-server/src/routes/events.ts`, `api-server/src/lib/analytics-store.ts` | New client `trackEvent` drops post/comment reaction, classification and vote reward event types before local writes or transmission. Mounted event endpoint now rejects **all** batches before storage, including other events; existing clients discard those batches on 403. Historical browser/DB/file/memory/backups are untouched. Client-side non-vote analytics, other routes, old deployments and direct writers remain unverified. Logging, opt-out/deletion across all sinks remain blockers. |
| `lib/recommendations.ts`, `lib/hive-mind.ts`, `lib/tsrg/feed.ts` | Legacy and prototype utilities can read vote and event data; local HomeFeed no longer invokes behavioral home/feed topic rankers. App startup no longer launches the hive maintenance runner, which is hard-disabled; legacy individual helpers remain exported and can mutate storage if directly called. Previously its pruning used vote scores and fossilization ranked comments, changed content state and awarded points. Other consumers and stored/cached data need review. Standalone ranking tests do not establish live eligibility. |
| `supabase/migrations/0001_initial_schema.sql`, `0006_tsrg_foundation.sql` | Local 0001 defines reactions and a public SELECT policy; 0006 defines tier and co-vote derived structures. **Do not assume these equal live policies**: inspect actual configuration before any approved change. Public SELECT, if actually effective, exposes individual votes. |
| `supabase/migrations/0007_identity_reactions_flags.sql`, `0008_set_post_reaction.sql`, `0009_reaction_preview.sql`, `0011_tiered_vote_foundation.sql`, `supabase/proposals/0012_tier_eligibility_v2.sql` | 0007/0008 and 0011/0012 define privileged writers; 0009 is a privileged vote-state reader; 0007 returns aggregates. Caller-controlled subject, role grants and bypasses require review. Local definitions are not evidence of live installation or actual permissions. |
| `supabase/proposals/0023_reaction_cas_experiment.sql`, `0024_reaction_writer_grants.sql`, `0025_reaction_two_step_experiment.sql` | Synthetic CAS/two-step and grants experiments only. Earlier tests show a privileged old writer bypasses the new two-step logic, and grant revocation alone breaks an API while leaving privileged bypasses. Do not deploy. |

## Evidence needed before activation

Reviewed complete database and application writer/reader inventory; approved isolated verification of actual role grants, RLS, function bodies/triggers, service-role and direct-client behavior; trusted account provisioning and mapped-identity lifecycle; server-authorized visibility and five-minute session checks; atomic per-user revisions and remove-then-choose enforced across **all** writers; idempotent retry receipts, concurrency, cross-device/account-switch and uncertain-result handling; privacy and deletion across analytics/cache/backups; safe recovery/restore; real web/Android/iOS end-to-end tests. An approved, verified recovery plan and explicit owner approval are required before any live mutation. No synthetic test substitutes for these requirements.
