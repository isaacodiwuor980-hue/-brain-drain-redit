# TSRG feed experiment

`VITE_EXPERIMENTAL_TSRG_FEED=true` opts the **For You** client into an experimental Wilson/age ordering of already loaded posts. It uses existing up/down reaction counts as unit-weight proxies, not staked reputation. The default and Following feed remain chronological. This does not change server pagination or select unseen candidates: later pages can reorder earlier ones. It preserves cold-start and invalid posts at the end and does not claim factual accuracy.

The module also supplies isolated primitives for fixed-point stake mass, tag-specific authority gating, a cluster bonus and CUSUM. They are **not wired to voting or server-side ranking**, because the existing database and API do not supply trusted stake tiers, per-tag authority, cluster identities, velocity baselines, or ring evidence. No client authority is trusted, no stake ledger/schema migration is applied, no accuracy labels are shown, and no 70/15/10/5 or fairness guarantee is asserted. The provided code's label thresholds, fairness rotation, ring-detection assumptions, moderation effects, identity mapping, privacy, calibration, and appeal process require independent design and validation before production use. `bigint` accumulation is exact, but Wilson and decay use floating-point math and are not bit-exact across all runtimes. Fixed-point totals outside the exact JS conversion range are rejected instead of silently capped.

The supplied code is not safely deployable unchanged: its invalid-score sentinel is not idempotent under `sanitize`; user-dependent rotation does not prove equal exposure; ring components can be distorted by duplicate edges; and engagement-based scores cannot establish truth. The source schema also assumes UUID post IDs whereas this repository uses text IDs. Do not apply it to a live database without migration review and backups. This experiment is not a security boundary and must remain disabled until evaluated.

## V2 foundation (not deployed)

The additive `toFixedV2` and `fromFixedV2` helpers saturate while the original strict functions remain unchanged. `effectiveMassV2`, `canStakeDetailed`, `clamp01`, `authorityComposite`, `winningClusters`, `bridgingBonusV2`, `discussionDepth`, `jaccard`, `badFaithPenalty`, `quantizeCommentScore`, `detectRings` and `ringIdentityOverlap` are isolated helpers tested in `v2.test.ts`. The ring detector deduplicates edges and ignores self-edges; it is a heuristic and is not evidence of abuse. Lexical overlap is not evidence verification. These helpers are not connected to live reactions, reputation, moderation or feed rankings.

`supabase/migrations/0006_tsrg_foundation.sql` adds tables and a legacy-compatible reaction tier default, but creates no jobs, hooks, historical velocity, labels or corpus views. It is tested on a simplified in-memory PGlite schema in `schema.integration.test.ts` and is **not applied** to any Supabase database. Historical `mouth` defaults do not mean users chose a confidence stake. Budget mass is stored as fixed-point BIGINT, not decimal. A deliberately separate `tsrg_jobs` table avoids conflicting with an existing jobs table. New tables have RLS enabled and direct anonymous/authenticated grants revoked; service-role access still needs explicit authorization checks in any future API. Review data access, retention, cohort fingerprint privacy, account identity mapping, backup, rollback, and permissions on real Supabase before deployment. Rollback comments drop collected data and require approval and backup.

The nine-phase rollout is incomplete. No authority gating, confidence UI, bridging labels, slashing, scheduler, data-collection hooks, adversarial damping, corpus API or stress benchmark is enabled. Keep the existing experimental feed flag unchanged. Do not claim production readiness or real-world accuracy from these isolated tests.

## Offline stake aggregation V3

`stake-aggregate.ts` adds an isolated, unwired aggregate of explicit up/down tiers using the existing fixed-point `effectiveMass` and Wilson helper. It rejects duplicate voter IDs, wrong tags and malformed inputs; callers must independently authenticate identities, verify tier eligibility and obtain trusted authority for the exact tag. It does not resolve the 0.10/0.15 policy conflict, infer tier choices, perform detection, move points or enable ranking. Risk flags are synthetic inputs only.

**Release blocker:** the existing Wilson helper uses a prior in its proportion but raw mass for its sample size. At small mass, it can give a higher lower-bound score after adding down-mass: with up=0.35 and down=0 the result is approximately 0.0539, while adding down=1.95 gives approximately 0.1065. Down-only mass can also receive a positive score. These are calculations, not empirical probabilities of truth. The new regression documents the behavior rather than changing legacy scoring. Compare and review an additive alternative before any live use; no fairness, accuracy or monotonicity claim is warranted from this prototype.

## Offline Wilson-prior comparison V3

`wilson-prior-candidate.ts` is an additive, unwired experiment. Unlike `wilsonLowerBound`, it adds the same symmetric pseudocount to both the proportion and the effective sample size. It changes scores and is not a drop-in correction or an approved new policy. On 10,000 deterministic synthetic **nonempty** fixed-point input pairs the test checks that adding up mass does not decrease, and adding down mass does not increase, the candidate score (within floating-point tolerance). This is a test of those inputs, not a proof of general correctness or calibration.

The no-vote score is explicitly zero to match the existing cold-start convention; the positive prior makes the first down-only vote yield a positive score. This discontinuity remains a release blocker. A synthetic scenario with one maximally weighted Life vote opposed by 99 minimum-mass Mouth votes also shows the minority can be outweighed. This scenario assumes inputs rather than demonstrating eligibility, independence or real expertise. No algorithm is guaranteed to recover truth from confidence-weighted votes; verify against independently labeled cases and assess cold-start behavior before considering a rollout. Neither the existing function nor live feed is changed.

## Offline reviewed-answer summary V3

`summarizeCalibrationV3` is an additive, unwired arithmetic experiment for synthetic reviewed answers in one topic. It reports the number of answers, fraction matching supplied keys, and mean uniform-guess baseline (`1/K` separately for each question), or no result when empty. It rejects duplicate IDs, wrong-topic records and invalid choice indexes. It uses no real data and does not compute a probability of expertise or a gate, grant public labels or change vote weights. A 10,000-question deterministic uniform-guess fixture tests the baseline; a separate test illustrates that correct answers alone cannot distinguish genuine knowledge from a leaked key. Real guesses may be biased. Authentication, genuinely independent key review, question quality, cross-topic evidence, cheating prevention, privacy, accessibility and real-world validation remain unresolved.

## Offline interest V4

`interest-v4.ts` is an unwired alternative to V3. It avoids halving tiny floating-point weights before division: with one positive exposure of weight `Number.MIN_VALUE` and an equal prior, V3 returns 1 rather than 0.75 due to underflow; V4 returns 0.75. The old export is unchanged. In 500 ordinary synthetic cases the two agree within test tolerance, not a proof of universal equivalence. Caller provenance, opt-out, downvote semantics and real-world feed validation remain unresolved.

## Offline personalized ordering V3

`rankOfflinePersonalizedV3` combines caller-supplied topic interest and a supplied quality proxy using an explicit test weight, and delegates stable ordering to the existing offline pipeline. It has no default production weight, candidate retrieval, quota, eligibility or live wiring. Missing topic scores are neutral; with personalization off, the supplied interest map is not read. This local property alone is not backend opt-out, deletion, truthful quality, safety or expertise verification. The caller must provide trusted data and enforce permissions and privacy; no downvote is interpreted as disinterest by this function. No actual feed behavior is changed.

## Offline Wilson-prior comparison V4

`wilson-prior-v4.ts` is a separate, unwired comparison. It uses the same prior for no votes that V3 applies to nonempty votes, removing V3's explicit zero-vote jump. It delegates nonempty calculations to V3 and does not change legacy or V3. In 10,000 synthetic pairs including cold start, tested vote additions moved in the expected direction within tolerance. A positive initial value is a policy trade-off and not evidence of quality or truth; its impact on new posts, fairness, calibration and actual users is unverified. This candidate is not approved for production ranking.
